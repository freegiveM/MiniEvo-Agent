# 有效告警率标注 rubric v1

**先写 rubric 再标**。顺序是有意的：先看数据再定标准，会不自觉地把标准
往"我已经相信的结论"上凑——想证明 agent 好，就会把边缘告警判成有效；
想证明它不行，就会反过来。标准先落定，判定过程才有约束。

本 rubric 定稿后**不再因为标注过程中遇到的具体样本而修改**。若确实发现
规则覆盖不到的形态，记在文末"待议形态"，进入 v2，不追溯改 v1 的标注。

## 这个数字测的是什么，不测什么

测：**单标注者**对 agent 告警有效性的判断，以及该判断的**自身重测一致率**。

不测：告警有效性的客观真值。只有一个标注者，报不出标注者间一致率
（inter-annotator agreement），因此这个数字**不能当作 ground truth 使用**。
报告里必须原样标成"单标注者 + 重测一致率 x%"，不能简写成"有效告警率 x%"。

为什么仍然做：重测一致率低意味着连"同一个人隔几天看"都对不上，那么这个
指标的任何绝对数值都不必讨论。它是一道**下限检验**，不是精度声明。

## 判定单元

一条告警 = agent 在一个 case 上产出的一个 finding。不是一个 case，
不是一个 PR。同一个 case 上的多条告警各自独立判定。

## 标签空间

四个互斥标签。刻意不用二分（valid / invalid）：二分会把"说对了但没用"
和"说错了"压到一起，而这两者对使用者的含义完全不同。

| 标签 | 含义 | 判定要点 |
|---|---|---|
| `valid` | 指出了一个真实存在的问题，位置与性质都对 | 位置能对上、描述的问题在代码里真的成立 |
| `valid-but-noise` | 问题真实存在，但不值得在这个 PR 里提 | 例如指出一处与本次改动无关的既有风格问题 |
| `invalid` | 描述的问题在代码里不成立 | 误读了代码语义、指向了不存在的调用、事实错误 |
| `unlabelled` | 落在标注集之外，无法判定对错 | 见下条，这是**口径要求**，不是偷懒 |

### `unlabelled` 为什么必须单列

数据集的 `expected_findings` 只标了种子缺陷。agent 报出一条标注集里没有的
问题，可能是真发现了别的缺陷，也可能是误报——**从标注集看不出来**。
把它计入误报会系统性低估 precision；计入命中会系统性高估。它是
"没有依据下判断"，和空分母报 None 是同一条纪律。

`unlabelled` 不进有效告警率的分母。分母 = valid + valid-but-noise + invalid。

## 判定顺序（固定，不得调整）

顺序固定是重测一致性的前提。同一条告警按不同顺序问，会得到不同答案。

1. **这条告警落在标注集范围内吗？** 不在 → `unlabelled`，停。
2. **它描述的问题在代码里成立吗？** 不成立 → `invalid`，停。
3. **这个问题与本次改动相关吗？** 不相关 → `valid-but-noise`，停。
4. 否则 → `valid`。

第 2 步在第 3 步之前：一条既不成立、又与改动无关的告警是 `invalid`，
不是 `valid-but-noise`。顺序反了会把事实错误洗成"噪声"。

## 具体判定规则

### 位置（第 1 步）

- 告警的 `path` 与 `line` 落在某条 `expected_finding` 的
  `[start_line, end_line]` ± 2 行内 → 在范围内。
- ±2 与评测的 `line_tolerance` 保持一致。不另取一个数：标注口径与
  自动评分口径不一致时，两边的数字就不能相互解释了。
- 告警指向的文件不在本次 diff 里 → `unlabelled`（不是 invalid）。
  agent 看不到那个文件的上下文，判它错没有依据。

### 事实成立（第 2 步）

判"成立"只看**代码本身**，不看 agent 的措辞是否好听。

- 描述的代码结构确实存在（那个调用、那个赋值、那个分支真的在） → 成立。
- 描述的因果确实可能发生（不要求已经发生，只要求路径存在） → 成立。
- 严重度判错**不影响**这一步。严重度另有 `severity_accuracy` 指标，
  在这里重复扣分等于把同一个错误算两次。
- CWE 编号判错同理，不在这一步扣分。

以下明确算 `invalid`：

- 声称某个变量未经校验，但代码里上游三行就有校验。
- 声称某函数会被外部输入触达，但它是模块私有且无调用点。
- 引用了代码里不存在的标识符。

### 相关性（第 3 步）

- 问题所在的行在本次 diff 的新增行里 → 相关。
- 问题在既有代码里、但本次改动使它可达或加重了它 → 相关。
- 问题在既有代码里、与本次改动无因果关系 → `valid-but-noise`。

## 边界情形的仲裁规则

这一节是重测一致率能不能站住的关键。没有明文仲裁，遇到模糊样本时的
判定就取决于当天的心情，重测一致率测的是情绪波动而非标准。

| 情形 | 裁定 |
|---|---|
| 告警把两个相邻缺陷合并成一条 | 按它主要描述的那个判；描述不可分辨则 `unlabelled` |
| 告警位置对、但解释文字答非所问 | 按代码事实判，解释文字不参与（措辞质量不是本指标） |
| 告警指向 diff 的删除行（`-` 行） | `unlabelled`。删除行不是本次引入的，标注集也不覆盖 |
| 告警指向测试文件 | `unlabelled`。数据集构造时排除了测试路径，标注集无覆盖 |
| 同一位置报出两条内容重复的告警 | 各自独立判定，不合并。去重是 precision 的事，不是有效性的事 |
| 拿不定主意 | 判 `unlabelled`，并记进"待议形态"。**不允许**为了凑数硬判 |

最后一条是刻意的：把犹豫样本硬塞进某一档，会让分母变大、看起来更可信，
实际是把不确定性藏起来了。`unlabelled` 占比本身就是要报的数字之一。

## 重测协议（test-retest）

- 从已标样本中抽 40 条，间隔 **≥3 天**重标。
- 第二轮**不得看到第一轮的标签**。看到就会锚定，一致率必然虚高——
  那测的是"我能不能记住上次选了什么"。工具层强制隐藏，不靠自觉。
- 第二轮**不得看到自己上次写的备注**，同理。
- 抽样用固定种子记录在案，保证两轮抽到的是同一批。
- 报一致率与 Cohen's κ。只报原始一致率会因为标签分布不均而虚高：
  若 90% 的样本都是 `valid`，随便乱标也能得到约 0.82 的一致率。
